## Affiliate links on GitHub and Hubitat

GitHub permits project-related promotional links in your own README, provided advertising is not its primary purpose. A useful build tutorial with a relevant parts list fits that general allowance. This is not a promise that Amazon has approved the particular repository. Add the exact public repository or GitHub Pages destination to the Amazon Associates website list and confirm it is accepted for your account.

The README includes the visible disclosure immediately above the BOM:

> As an Amazon Associate I earn from qualifying purchases.

It also expressly says that the BOM links are affiliate links and commissions may be earned. All ten US links use `tag=hcdp-20`. The review checks link construction, not tag ownership or Amazon's actual commission attribution.

For Hubitat, the reviewed public guidelines prohibit spam and do not provide explicit blanket approval of affiliate links. Direct tagged links should be used only if the placement is acceptable to both Amazon and Hubitat. A straightforward approach is a short forum build summary linking to the GitHub tutorial/BOM, with a note that the BOM contains affiliate links. This does not require publishing the entire manual as a forum reply.

Hubitat's current guidelines also ask users to disclose substantial AI assistance and prefer a concise summary/link over long AI-generated posts. A suitable disclosure for a post adapted from this work is: “I used AI assistance to organize and edit the documentation. The linked BOM contains affiliate links.” Do not claim a technical review that has not happened.

The earlier blanket warning about downloadable manuals should not be read as a ban on an online GitHub README. A separately distributed ebook or printed guide needs its own Amazon policy check. Avoid publishing unapproved Amazon product imagery, copied reviews, star ratings or static prices; the kit uses the author's photos and text product descriptions.
